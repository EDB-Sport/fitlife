# TEAM analyzers

The project's own Roslyn rules (`docs/CSHARP_SETUP_TODO.md` section 4). Each rule is a compiler error with a message in the form "Found X. Do Y in Z.", so an agent reads the fix along with the error.

| Folder | What |
|---|---|
| `Team.Analyzers/` | The analyzers (`netstandard2.0`, the target the compiler loads) |
| `Team.Analyzers.Tests/` | NUnit tests: for each rule, snippets that must raise the diagnostic and snippets that must not |

## Rules

| ID | Rule | Analyzer |
|---|---|---|
| TEAM002 | No NLog API (`LogManager`, `NLog.Logger`, `NLog.ILogger`) outside `Program.cs`. Classes inject `ILogger<T>`. | `NlogOnlyInProgramAnalyzer` |
| TEAM003 | An `ILogger` call (`Log`, `LogInformation`, …, `BeginScope`) whose template placeholders or arguments have a name containing `password`, `token`, `secret`, `connectionString`, `jwt` or `cpr` (any case). Log an id or a masked value instead. | `NoSecretsInLogsAnalyzer` |
| TEAM004 | `#pragma warning disable` and `#nullable disable` end with `// #<issue>: <reason>` on the same line. `[SuppressMessage]` and `[UnconditionalSuppressMessage]` have `Justification = "#<issue>: <reason>"`. | `JustifiedSuppressionAnalyzer` |
| TEAM005 | No `dynamic`, no `goto` (also `goto case`/`goto default`), no LINQ query syntax, no conditional expression inside another one, and no lambda or anonymous method nested more than one level deep (a lambda inside a lambda is fine). | `ReadabilityLimitsAnalyzer` |
| TEAM006 | Every NUnit test (`[Test]`, `[TestCase]`, `[TestCaseSource]`) calls an NUnit assert class (`Assert`, `ClassicAssert`, `StringAssert`, …) or a Moq `Verify*` in its own body. `Assert.Pass`/`Ignore`/`Inconclusive`/`Warn` don't count. | `TestHasAssertionAnalyzer` |
| TEAM007 | No `Thread.Sleep` and no `Task.Delay` in test projects (assembly name `*.Tests` or `*.IntegrationTests`). Advance a `FakeTimeProvider` instead. `Task.Delay` with a `TimeProvider` argument is allowed. | `NoWaitInTestsAnalyzer` |
| TEAM008 | Every public, non-nested type in a `*.Models` namespace is named in the **In code** column of `GLOSSARY.md` (in backticks), which the build passes in as an AdditionalFile. | `ModelTypesInGlossaryAnalyzer` |
| TEAM009 | Every controller action (a public instance method of a `ControllerBase` subclass, not `[NonAction]`) has an `[HttpGet]`/`[HttpPost]`/… attribute and returns `ActionResult<T>` or a typed result from `Microsoft.AspNetCore.Http.HttpResults`, also inside `Task<>`/`ValueTask<>`. | `ControllerActionContractAnalyzer` |
| TEAM010 | No string literal (plain, verbatim, raw or the text of an interpolated string) containing `http://`, `https://`, `mongodb://` or `amqp://` in a file under `src/`. Read the address from configuration. | `NoHardCodedUrlsAnalyzer` |
| TEAM012 | No conditional expression (`?:`) as a return value, an assigned value or a variable initializer. Write `if`/`return`, or `if`/`else` with an assignment in each branch. Elsewhere, for example as an argument, it is allowed. | `ConditionalExpressionAnalyzer` |

The other rules in section 4 come one PR at a time (issue #9 and its sub-issues).

### TEAM004 in practice

```csharp
#pragma warning disable CA1822 // #42: the method is part of the generated client's contract
#nullable disable // #42: the generated client has no nullable annotations yet

[SuppressMessage("Style", "IDE0060", Justification = "#42: the parameter is required by the interface")]
```

- The issue reference is a GitHub issue in this repo, a colon, and the reason. A comment on the line above doesn't count.
- `#pragma warning restore`, `#nullable enable` and `#nullable restore` need no comment.
- Generated code (`// <auto-generated/>`, `*.g.cs`, Razor output) is skipped.
- TEAM004 can't switch itself off. `#pragma warning disable TEAM004`, `[SuppressMessage(..., "TEAM004")]` and `dotnet_diagnostic.TEAM004.severity = none` in an `.editorconfig` or `.globalconfig` are all ignored. The descriptor is tagged `NotConfigurable` (pragmas and severity settings) and `Compiler` (Roslyn ignores `[SuppressMessage]` for compiler diagnostics). The only way to make the error go away is the issue reference.

## Adding a rule

1. Open (or pick) the issue for the rule. One rule per PR.
2. **Test first.** Add `<Name>AnalyzerTests.cs` in `Team.Analyzers.Tests/` with snippets in markup: `{|TEAM00X:code|}` marks where the diagnostic must be reported, and every unmarked diagnostic fails the test. Cover both: snippets that raise the rule and snippets that don't. Run the tests and see them fail.
3. Add `<Name>Analyzer.cs` in `Team.Analyzers/`:
   - severity `Error`, enabled by default
   - a message of the form "Found X. Do Y in Z."
   - `context.ConfigureGeneratedCodeAnalysis(GeneratedCodeAnalysisFlags.None)` and `context.EnableConcurrentExecution()`
4. Add the rule to `Team.Analyzers/AnalyzerReleases.Unshipped.md` (release tracking, RS2008 fails the build otherwise) and to the table above.
5. `dotnet test -c Release` from the repo root.

Tests compile the snippets against the .NET 10 reference assemblies (`ReferenceAssemblies.Net.Net100`). The test framework downloads them from NuGet the first time, so the first run needs network access.

## Versions

Package versions are in the root `Directory.Packages.props`. `Microsoft.CodeAnalysis.CSharp` stays at the Roslyn version of the SDK floor in `global.json` (5.0.0 for SDK 10.0.100): a compiler doesn't load an analyzer built against a newer Roslyn than itself (warning CS8032, an error here). Raise both together.

## How the analyzers reach the services

Not wired in yet: the rules run only in the tests of this folder. Section 4 of `docs/CSHARP_SETUP_TODO.md` wires them into every project from the root `Directory.Build.props`, a code-owned file, in a PR of its own:

```xml
<ItemGroup Condition="'$(MSBuildProjectName)' != 'Team.Analyzers' And '$(MSBuildProjectName)' != 'Team.Analyzers.Tests'">
  <ProjectReference Include="$(MSBuildThisFileDirectory)tools/Analyzers/Team.Analyzers/Team.Analyzers.csproj"
                    OutputItemType="Analyzer" ReferenceOutputAssembly="false" />
</ItemGroup>
```
